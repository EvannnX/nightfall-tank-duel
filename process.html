SESSION 3 · BUILD WITH AN AGENT

A playable game and a visible process

Nightfall was built through repeated student direction, implementation, testing, rejection, and revision. This timeline is concise; the full chronological evidence remains in the development log.

Why Track A

The project uses HTML, CSS, plain JavaScript, and Canvas 2D with no build step or runtime dependencies. This is the lowest necessary dependency track: side-view ballistic motion and a deformable heightmap are clearer and lighter in 2D than in a 3D engine.

Development Timeline

01 · FIRST PLAYABLE

Brief to ballistic loop

Implemented angle, power, wind, four weapons, destructible terrain, health, turns, AI, and model tests. The result worked but still looked and felt like a lab prototype.

02 · VISUAL DIRECTION

Full-window night battlefield

The student requested realism, a visible portal, and removal of non-gameplay slogans. The presentation moved toward the supplied night-valley reference without changing the 2D simulation.

03 · CONCEPT DRIFT

Training lab to competitive duel

The student chose full opposition, limited movement, a 1.5× map, realistic sampled audio, and English-only UI. The AI selected exact movement values and implementation details.

04 · COMPLETENESS

Aligned aim and full game flow

A shared muzzle transform fixed barrel/guide/projectile disagreement. Responsive camera behavior stopped stretching. Landing, intro, setup, help, pause, result, and rematch completed the journey.

05 · RELEASE

Public repository and Pages

The static site was published at GitHub Pages from the public repository. Physics/model checks passed before the first release.

06 · COURSE AUDIT

Three sessions made explicit

The project home became an exhibition; Session 1 analysis, the system graph, Session 2 relationships, concept drift, and a chronological Session 3 log were added without inventing student reflection.

Student Decisions and AI Influence

Student-owned direction

Competitive play; limited movement; 1.5× world; realistic night presentation and sounds; English-only interface; complete onboarding; separate AI and local-player modes; public deployment.

AI implementation choices

Canvas 2D; fixed-step physics; 60 m/6 m movement values; search-based AI; portrait camera/minimap; exact weapon tuning; exhibition/game separation.

Unchanged design core

Angle, power, wind, destructible terrain, visible shot evidence, and the observe → judge → act → feedback → adjust loop.

Verification

  • Automated checks cover movement budget and reversal, walls and tank collision, damage and craters, projectile termination, muzzle/velocity alignment, cluster origin, and all three maps at wind extremes.
  • The world is 2160 × 670—1.5 times the original 1440 width.
  • Required assets are local and Pages-safe; internal links are relative.
  • Landscape uses a full battlefield view; portrait uses follow/overview modes without geometric stretching.
  • Known limits: no network multiplayer, no cave-like terrain overhangs, and browser-native fullscreen/audio require user interaction.
